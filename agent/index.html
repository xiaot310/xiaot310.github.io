02 / ARCHITECTURE

两层，不是一套“假装有权限”的网站。

GitHub Pages 没有登录和按人授权。所以站点明确分成两层：公开层放愿意让任何人看的内容； 本地层只绑定 127.0.0.1，放文件、LaTeX、计划和笔记。分享公开链接不会顺带分享私有层。

一句话判断新内容放哪

愿意让任何拿到链接的人看到 → content/ 或公开页面；需要登录、含个人路径、未发表数据、审稿意见 → workbench/ 本地层；含 token → private.json，永不提交。

03 / CONTENT

加一张卡，只需要改数据。

首页的研究、项目、当前焦点都由 content/site-content.js 渲染。 HTML 只留骨架，assets/js/home.js 负责把数组变成卡片。不要复制首页 HTML 来加内容。

  1. 改数组在 research、projects 或 focus 里加一个对象，保持字段完整。
  2. 写公开摘要只写愿意公开的问题、方法、阶段；不要放未发表数据、合作方材料或审稿意见。
  3. 刷新验证静态服务器打开首页，确认新卡片出现、控制台无报错、390px 无横向溢出。
  4. 同步文档如果改了字段名或布局，更新 content/README.md 和 home.js；结构变化再更新本页与 manifest。

研究卡示例

{

04 / WORKBENCH

本地层：文件、LaTeX、计划与笔记。

工作台由 workbench/server.py 提供，只绑定 127.0.0.1。公开部署时页面会显示 “本地服务未连接”，文件与 LaTeX 按钮自动禁用；这是预期行为，不要伪造在线。 

cd xiaot310-site
python workbench/server.py
# → http://127.0.0.1:8765/workbench/
端点作用边界
/api/status服务状态、工作区根路径只读
/api/files最近文件 / 搜索只扫 roots；排除敏感目录
/api/toolsLaTeX 是否配置不返回私链
/api/open系统默认程序打开仅 researchRoot 内
/api/reveal资源管理器定位仅 researchRoot 内
/go/latex302 到私有项目链接不进公开页面

安全底线

只绑 127.0.0.1；private.json 静态访问返回 404；POST 只接受同源 JSON；拒绝 .. 越界、敏感目录和私链文件；默认排除个人文件、奖学金、身份证、学历、学位、宿舍、比赛。

启动参数、配置字段、备份与常见问题见 workbench/README.md。

关于“权限”

GitHub Pages 是公开静态托管，不能按用户授权。需要“只给某些人看”时，必须另做带登录的后端；当前站点的策略是公开内容公开、私有内容只在本机，而不是假装有访问控制。

06 / VERIFY

每次改完，跑一遍可验证的清单。

自检只检查静态文件是否可读、manifest 是否可解析、内容数据是否存在；工作台 API 是可选检查，离线不算失败。

未运行
  • 点击“运行自检”，会请求 manifest、内容数据、llms.txt、工作台页面；本地 API 仅作可选提示。

必须通过

  • 首页、演示、Agent、工作台页面可打开
  • 首页数据卡来自 content/site-content.js
  • 390px 无横向溢出，控制台无报错
  • 公开层不含私链/token/个人材料

本地可选

  • /api/status 返回 ok
  • /api/files 不含敏感目录
  • /workbench/private.json 返回 404
  • /go/latex 只在本机 302
